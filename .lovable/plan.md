# إصلاح جذري لتعطل مولّد القصص

## الدليل المثبت
- نفّذت طلب تخطيط قصة حقيقي على الإنتاج بحساب العميل، وأعاد Backend Core الرمز `503 / AI_PROVIDER_TEMPORARILY_UNAVAILABLE` مع رقم تتبع.
- Lovable Cloud وقاعدة البيانات والمصادقة تعمل بصورة طبيعية.
- نقطة صحة الـVPS تعمل، وتؤكد أن مولّد النص المستخدم هو Gemini وأن خدمة Python معطلة؛ إذن الفشل في مسار NestJS → Gemini، وليس الصور أو PDF أو قاعدة البيانات.
- لا توجد مكالمات نص فاشلة في Lovable AI Gateway خلال نفس الفترة، لأن مولّد النص لا يستخدمه أصلًا.

## التعديل المقترح
1. تعديل مزود النص في Backend Core ليستخدم نموذج Gemini أساسيًا ونموذجًا احتياطيًا قابلًا للضبط عند فشل **مؤقت فقط** مثل 429/5xx/timeout.
2. إبقاء الحد الإجمالي للمحاولات محدودًا وتحت مهلة واجهة العميل، دون إعادة إرسال طلب إنشاء القصة نفسه ودون خصم أو حفظ مكرر.
3. عدم الانتقال للنموذج الاحتياطي عند أخطاء المفاتيح والصلاحيات والنموذج غير المدعوم ورفض المحتوى.
4. إضافة سجل آمن يوضح النموذج والمرحلة وحالة المزود ورقم التتبع، بلا prompts أو مفاتيح.
5. تحديث إعدادات البيئة الموثقة وفحص الجاهزية ليظهرا تهيئة النموذجين دون كشف أسرار.
6. إضافة اختبارات: نجاح الأساسي، انتقال للاحتياطي بعد عطل مؤقت، عدم الانتقال عند خطأ دائم، واستنفاد محدود يعيد 503 واضحًا.

## التحقق
- تشغيل اختبارات مزود النص واختبارات مسار إنشاء القصة في Backend Core.
- تشغيل فحص TypeScript الخاص بالـBackend Core.
- إعادة اختبار طلب خطة حقيقي واحد بعد نشر نسخة الـVPS فقط؛ ثم اختبار قصة كاملة من الموقع المنشور إذا نجح التخطيط.

## قيد النشر
التعديل سيكون جاهزًا داخل مصدر Backend Core، لكن نشره على `najmah-api.nextnext-gen.com` يحتاج قناة نشر الـVPS الحالية. لن أغيّر Lovable Cloud أو قاعدة البيانات أو الصور أو PDF.
