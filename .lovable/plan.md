
# ما ينقص لإكمال "Starry Tales / NajmaH" وتسليمه للعميل

بناءً على تحليل `.lovable/plan.md`، الكود الحالي، وقاعدة البيانات. مرتّب حسب الأولوية مع **الهدف من كل بند** حتى تقرر أي بنود تدخل في نطاق التسليم.

---

## 🔴 P0 — حواجز تسليم (لا يمكن التسليم بدونها)

### 1. Trigger إنشاء Profile للمستخدمين الجدد
- **الوضع:** دالة `handle_new_user` موجودة بدون trigger على `auth.users`.
- **النتيجة الحالية:** أي مستخدم جديد لا يُنشَأ له `profile` ولا `user_role` — الأدوار والصلاحيات معطّلة فعلياً.
- **الهدف:** ضمان أن كل تسجيل جديد ينتج عنه صف في `profiles` + دور `user` تلقائياً.

### 2. Endpoint لاعتماد المدفوعات اليدوية (`approve-payment`)
- **الوضع:** جدول `manual_payment_requests` موجود، لكن لا يوجد UI ولا edge function لاعتماد الطلب.
- **النتيجة الحالية:** الأدمن مضطر يكتب SQL يدوياً لتفعيل اشتراك أي عميل دفع.
- **الهدف:** يضغط الأدمن "اعتماد" → يُنشأ صف في `user_subscriptions` تلقائياً + إشعار للعميل.

### 3. Cron لانتهاء الاشتراكات (`expire-subscriptions`)
- **الوضع:** `has_paid_feature` يحترم `expires_at` ✅ لكن لا أحد يضع `status='expired'`.
- **الهدف:** بيانات نظيفة في الـ Dashboard + إمكانية إرسال تنبيهات تجديد.

### 4. تأكيد عمل الـ Free Trial بعد الإصلاحات الأخيرة
- **الوضع:** الكود موجود، لكن لم نختبر دورة كاملة end-to-end (fingerprint → 3 صفحات بصور → تسجيل خروج وتأكد المنع).
- **الهدف:** أهم CTA للزائر — لازم تشتغل قبل التسليم.

---

## 🟠 P1 — وظائف مُعلَن عنها لكن غير مكتملة

### 5. فحص الملفات المرفوعة (`scan-file` worker)
- **الوضع:** جدول `file_scan_jobs` يستقبل jobs لكن لا processor — الصور تُقبل بدون فحص فعلي.
- **الهدف:** أمان أساسي (مشروع للأطفال = مسؤولية قانونية على المحتوى المرفوع في مسابقات الرسم).

### 6. Streak تحديث server-side (`update-streak` edge function)
- **الوضع:** يُحدَّث من المتصفح فقط، قابل للتلاعب.
- **الهدف:** Gamification موثوقة وعرض إحصائيات حقيقية للأهل.

### 7. تفعيل Bedtime Mode تلقائياً
- **الوضع:** جدول `bedtime_schedules` موجود + Roadmap يذكره، لا UI ولا hook فعّال.
- **الهدف:** بيع رئيسي للأهل (تحكم أبوي حقيقي في وقت النوم).

### 8. حذف الـ Mock Data من صفحات الإنتاج
- **الوضع:** `mockBlog.ts`, `mockCompetition.ts`, `mockStore.ts`, `adminMockData.ts` لا تزال مستخدمة.
- **الهدف:** عرض بيانات حقيقية من قاعدة البيانات بدل وهمية في Blog/Competition/Store.

### 9. حذف أو ربط `get-file-url` edge function
- **الوضع:** Function غير مستدعاة من أي مكان.
- **الهدف:** نظافة الكود وتقليل سطح الهجوم.

## 🟡 P2 — تحسينات جودة قبل التسليم

### 10. إشعارات بريدية (Lovable Emails)
- **الوضع:** لا قوالب مخصصة لـ: ترحيب، تأكيد دفع، اقتراب انتهاء اشتراك، طفل أكمل قصة.
- **الهدف:** تجربة مستخدم احترافية + احتفاظ بالمستخدمين.

### 11. SEO Production-ready
- **الوضع:** يحتاج فحص: meta tags لكل صفحة، sitemap محدّث، JSON-LD للقصص.
- **الهدف:** Discovery عضوي من Google.

### 12. Subscription Webhook (لو فيه نية لـ Stripe/Paddle)
- **الهدف:** أتمتة الدفع بدل الاعتماد الكلي على Manual Payments.

### 13. مراجعة سياسات RLS شاملة + Security Scan
- **الهدف:** التأكد من عدم وجود تسريب بيانات أطفال (حساسية قصوى).

## 🟢 P3 — ميزات Roadmap (اختيارية للإصدار الأول)

### 14. TTS كامل (بديل ElevenLabs المجاني)
- **الهدف:** تقليل تكلفة الصوت في الخطة Free.

### 15. توليد فيديو القصة (`generate-story-video`)
- **الوضع:** حقول `video_embed_url`/`videoPrompt` موجودة بدون generator.
- **الهدف:** Tier أعلى مدفوع (Premium).

### 16. جدولة `cleanup_*` functions
- **الهدف:** صيانة DB تلقائية (تنظيف rate_limit + upload_pipeline القديم).

## سؤال قبل التنفيذ

عشان أحدّد نطاق التسليم بدقة، اختر واحد من:

- **(أ) نطاق أدنى للتسليم:** بنود P0 فقط (1–4) → جاهز للإطلاق الأولي خلال أيام.
- **(ب) نطاق احترافي:** P0 + P1 (1–9) → منتج كامل مع أمان وتنظيف.
- **(ج) نطاق كامل:** P0 + P1 + P2 (1–13) → جاهز للنمو والتسويق.
- **(د) خصّص بنود:** أخبرني بأرقام البنود اللي عايز ندخلها في خطة التنفيذ.

بعد ما تختار، أرجع بخطة تنفيذ مفصّلة بترتيب العمل والتبعيات.
