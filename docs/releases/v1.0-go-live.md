# Najmah MVP v1.0 Go-Live Checklist

## Security ✅
- [ ] `.env.production` contains secure, strong secrets (JWT, DB passwords).
- [ ] Frontend uses `CORS_ALLOWED_ORIGINS` correctly.
- [ ] HTTPS enforced across frontend and backend.
- [ ] RLS policies applied to all public tables in Supabase.

## Database ✅
- [ ] Production project created on Supabase.
- [ ] All migrations pushed successfully (`npx supabase db push`).
- [ ] Auth providers configured.
- [ ] Storage buckets created (if applicable).

## Backend ✅
- [ ] NestJS API deployed to production hosting (e.g., Railway).
- [ ] Health endpoint (`GET /api/v2/health`) returns `{"status":"ok","version":"1.0.0"}`.
- [ ] Backend is communicating with Supabase Production successfully.
- [ ] Graceful shutdown hooks active.

## Frontend ✅
- [ ] Vite React application deployed to production hosting (e.g., Vercel).
- [ ] `VITE_API_URL` points to the production backend endpoint.
- [ ] Custom domain linked and DNS propagated.
- [ ] No `localhost` URLs remain in API calls.

## AI Provider ✅
- [ ] `GEMINI_API_KEY` configured in the backend environment.
- [ ] AI prompt generation verified to be working in production.
- [ ] AI output conforms to validation checks without errors.

## Monitoring ✅
- [ ] Backend platform logging is active.
- [ ] Database health dashboards are accessible.
- [ ] Alerts configured for critical endpoints (optional but recommended).

## Backup ✅
- [ ] Supabase Point-in-Time Recovery (PITR) or daily backups active.
- [ ] Codebase safely backed up to primary Git repository (e.g., GitHub).

## Rollback Plan ✅
- If a severe bug is discovered post-launch:
  1. Frontend: Revert Vercel deployment to the previous stable build with a single click.
  2. Backend: Redeploy the previous Git commit tag via the Railway dashboard.
  3. Database: Avoid destructive schema rollbacks. Rely on backups if data corruption occurs.
