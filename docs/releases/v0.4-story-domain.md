# Release v0.4: Story Domain & Lifecycle

## Overview
This release completes Sprint 4, establishing a production-ready, strictly-typed Story Domain inside `backend-core`. It lays the architectural foundation for the upcoming AI generation pipeline by defining the complete story lifecycle, creating necessary abstractions, and enforcing database security.

## Key Accomplishments
- **Database Architecture**: 
  - Created the `story_requests` table with foreign keys to `auth.users` and `child_profiles`.
  - Introduced the `story_status` enum to strictly track the state machine (`draft`, `queued`, `generating`, `generated`, `illustrating`, `narrating`, `completed`, `failed`).
  - Enforced Supabase Row-Level Security (RLS) policies for secure multi-tenant access.

- **Backend Core**:
  - Implemented the `StoriesRepository` pattern to isolate Supabase logic from the domain layer.
  - Refactored `StoriesService` to be a pure domain service orchestrating AI contexts and the repository.
  - Added strongly-typed DTOs (`CreateStoryRequestDto`, `UpdateStoryStatusDto`) and internal interfaces (`StoryMetadata`).
  - Added comprehensive REST endpoints in `StoriesController`.

- **Type Safety & Testing**:
  - Automatically synced TypeScript definitions for the database schema.
  - Passed all strict TypeScript compilation checks (`tsc --noEmit`).
  - Achieved full unit test coverage for the repository, service, and controller using isolated mocking of Supabase and internal context services.

## Next Steps (Sprint 5)
With the domain abstractions in place, the next phase will focus on the AI Pipeline (Planner, Writer, Validator) execution, transitioning requests from `queued` to `generated`.
